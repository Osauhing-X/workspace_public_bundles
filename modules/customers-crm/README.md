# Customers Crm

This external package now provides private administration and package-owned data handlers through Core's isolated persistence bridge. The original customer/company editor components are adapted without the old tenant navigation/header. Customers, companies and follow-up activities retain the original fields: stage, value, tags, notes, contact information, linked company/customer and deadlines. Search, completion/reopening, archive/restore and stage/tag settings work without provider keys. Row selection uses keyboard-accessible buttons; failed saves retain drafts.

Supabase is an optional future connector, not a prerequisite for these instance-local records. No Supabase table, key or legacy remote data was changed, imported or silently migrated. External Audience/Booking/Rent lead aggregation, the original source/relationship graph and staff-specific permissions are not yet restored. Access currently follows Core's administrator authorization. There is deliberately no Website/public export or public submission handler for private CRM data.

Tests verify business operations, validation, relationship retention and restoration constraints. The cross-repository `tests/crm_core.test.mjs` verifies this actual package via Core's restricted child process and disk persistence across calls, and rejects cross-instance relationships/public export. Provider synchronization and deployed visual workflows still require separate acceptance. Core limits state size; this version supports at most 1,000 records per collection and fails safely rather than truncating.
